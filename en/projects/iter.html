03 / Navigation and accessibility

ITER

One route.
Three ways to read it.

An educational navigator for a fictitious building. Passage constraints, a 3D model, an SVG plan and written steps describe the same route.

Open application ↗Source code ↗
  • React
  • TypeScript
  • Three.js
  • SVG
  • Web Speech

Independent project. Design, implementation and verification are documented in the source.

01

The starting point

A start, destination and passage conditions: width, slope, stairs and lift availability. All data belongs to the educational model.

02

The result

A route with distance, explained constraints, steps, 3D and SVG representations. Select a step from any view.

03 / Case study

Under the surface

  1. 01

    The planner filters graph edges by the constraints and finds the shortest available route. Closed sections and unknown conditions are explicit.

  2. 02

    Text, SVG and Three.js share node and edge IDs. Without WebGL, the route remains available as a plan and written steps.

  3. 03

    Web Speech API reads the route on request. The educational obstacle wall sends reports through its existing public service with server validation.

04 / Case study

Practical boundaries

A fictitious building and illustrative geometry. Results do not certify the accessibility of a physical space. Voices depend on the browser; the report wall depends on a separate service.
